# FFmpegで動画を扱うときの注意点

FFmpegの呼び出しは`setlog_join/ffmpeg.py`にまとめ、引数はリストで渡す。元動画は読むだけにし、書き出しは`output/`か`.setlog-join/`に限る。

## 速度の変更

映像の速度は`setpts`フィルタで変える。表示時刻（PTS）に係数を掛けるので、2倍速なら`0.5`、0.5倍速なら`2.0`を掛ける。

```bash
ffmpeg -i in.mp4 -vf "setpts=0.5*PTS" -an out.mp4
```

速度ごとのフィルタは次のとおり。

| 速度 | フィルタ |
| --- | --- |
| 0.5倍速 | `setpts=2.0*PTS` |
| 1倍速 | なし |
| 1.5倍速 | `setpts=PTS/1.5` |
| 2倍速 | `setpts=0.5*PTS` |

MVP（Minimum Viable Product、最初に公開する版。マイルストーンM1からM3まで）では音声を出力しない（`-an`）。音声を残すことになった場合は、音声側にも速度の変更が要る。

## 結合

- `concat`フィルタは、すべての区間で映像と音声のストリームの数がそろっている必要がある
- 解像度や画素形式が違う区間は、同じ形にそろえてから結合する。`join`は、最初のパネルの大きさに縦横比を保って`scale`で収め、余白を`pad`で黒く埋める
- `join`は、パネルを1本ずつ同じ解像度・フレームレート・コーデックの一時ファイルに変換し、concatデマルチプレクサ（`-f concat`）で再エンコードせずにつなぐ。一つのコマンドに入力を並べる方法と違い、パネルが数百件あっても入力の数が増えない

## 切り出し

- 位置を指定して切り出すときは、`-ss`と`-t`を`-i`の前に置く。再エンコードするので、フレーム単位で正確に切り出せる
- `crop`の幅・高さ・位置は偶数にそろえる。H.264の`yuv420p`は色差を2画素単位で持つため、奇数だと色がずれるか、エンコーダー（libx264）がエラーを返す

## 黒いフレーム

Setlogの書き出しでは、ある人の素材がほかの人より短いと、その人のカードの中身が描かれず、黒いまま書き出される。`scan`は、中身のあるパネルの先頭と末尾に続く黒いフレームを数え、書き出しと結合の区間から除く。

- 黒の判定は、縮小フレームでのカードの中身の輝度の中央値が3以下であること
- 除くのは先頭と末尾それぞれ3フレームまで。暗い映像を削りすぎないため
- 判定結果は解析結果のキャッシュに保存する

## 解析

- フレームを`numpy`で扱うときは、`-f rawvideo -pix_fmt gray`で標準出力に出し、`np.frombuffer`で読む
- 境界の検出は64×36に縮小した画像で行い、カードの検出と、パネルが空かどうかの判定は元の解像度の1フレームで行う

## テスト

- テスト用の動画は`lavfi`の`color`や`testsrc`で生成し、`vstack`で3段に重ねる
- 実動画で見つかった失敗は、生成した動画か`numpy`の配列で再現してテストに残す
