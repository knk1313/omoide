# エラー処理の方針

利用者はスマホだけを見ていて、Macのターミナルは見ていない前提で設計する。エラーが起きたら、何が起きたかと、次に取る操作をスマホの画面に短く示す。原因の詳細はMacのターミナルに残す。

## 文言の決め方

- 文言は「起きたこと」と「次に取る操作」の2つにする（例：「Macの空き容量が足りません。不要なファイルを削除してから、もう一度お試しください」）
- 利用者向けの文言は、サーバーがAPIの`detail`に入れて返す。画面はそのまま表示する
- 例外の型名、ファイルのパス、FFmpegの出力は画面に出さない。Macのターミナルに出す

## 場面ごとの表示

| 場面 | 例 | 表示のしかた |
| --- | --- | --- |
| この端末からは使えない | 共有URLを開いていない（404）、期限切れ（410）、Macにつながらない | 画面全体を案内に切り替える（`ShareProblem`） |
| ログインが要る | 401 | パスワード画面へ移り、ログイン後に元の画面へ戻る |
| 操作が失敗した | 採用・除外や速度の保存に失敗 | 画面を元に戻し、上のお知らせ（トースト）で知らせる |
| 始められない | 採用0件（422）、空き容量不足（507）、受け取れない動画（415・413） | その操作の近くに文言を出し、選び直しや再試行のボタンを置く |
| 途中で失敗した | 生成や解析の失敗 | 進み具合の表示を文言に置き換え、「もう一度試す」を置く |
| 再生できない | 動画を読み込めない | 再生枠の下に文言と「もう一度読み込む」を出す |
| 画面のコードの予期しないエラー | 描画中の例外 | 画面全体を「問題が起きました」に切り替え、再読み込みのボタンを置く |

## サーバー

- 予期しない例外は、ターミナルにトレースバックを出し、画面には500と「Mac側で問題が起きました。もう一度お試しください」を返す
- 送られた内容の形が正しくないとき（FastAPIの検証エラー）は、422と「送られた内容が正しくありません。画面を再読み込みしてから、もう一度お試しください」を返す。検証の詳細の一覧は返さない
- 裏で動く生成や解析の失敗は、ジョブの`error`に利用者向けの文言を入れる。進行中のまま残さない

## 通信

- APIの要求は15秒で打ち切り、Macにつながらないものとして扱う。Macがスリープした直後は、応答が返らないまま待たされるため
- 進み具合を取りに行く要求は、続けて3回失敗するまで再試行する。Wi-Fiが一瞬途切れただけで作業を止めないため
- 動画を送っている間に画面を閉じようとしたら、ブラウザの確認を出す

## お知らせ（トースト）

- 画面の上、手順の表示の下に出す。下に固定した操作のボタンと重ねない
- 成功は3.5秒、エラーは6秒で消える。タップでも消せる
- エラーは`role="alert"`で、読み上げでもすぐに伝える
